# MiroFish 强制场景验证协议

MiroFish 用于压力测试候选的采用障碍、替代关系、竞争响应和反向证据，不负责预测销量，也不把 Agent 表态换算为消费者购买率。每次技能运行都必须实际执行本协议；未完成时，整次运行不得给出优先开发、预售或可售产品图结论。

## 1. 运行位置与输入包

在候选生成、匹配竞品与反例检索、社会及政策证据整理之后运行，在最终排序、产品定型、出图和预售建议之前运行。输入包至少包含：

- 每个候选的产品形态、目标人群、使用场景、拟解决问题和增量机制；
- 高度匹配现有款、增长/平台/下降样本、低星反馈和已知反例；
- 已核验的 Amazon、Reddit/X、达人内容、社会与政策证据及其时间、区域和口径；
- 候选的失效条件、尚未证实事项和负面校验卡；
- 对抗角色：目标用户、怀疑者、现有竞品或卖家、合规/政策角色，以及与场景相关的渠道或场地角色。

种子信息必须标为“输入事实/刺激材料”，不得在结果中冒充 Agent 自主产生的证据。

## 2. 运行前检查

1. 确认 MiroFish 后端、模型接口和 Zep 均可访问，记录运行日期、模型名和关键配置；不得在报告或日志中泄露密钥。
2. 检查上下文容量。提示词、图谱资料和输出预留之和必须低于模型窗口；出现截断、配置解析缺失或输出残缺时先调整容量/压缩输入并重跑，不能把残缺结果当通过。
3. 为本次候选建立新的项目、图谱和模拟，避免旧项目记忆污染；保存项目 ID、图谱 ID 和模拟 ID。
4. 核对活动时间配置。若系统生成 `[起始小时, 结束小时]`，应按设计展开为完整小时区间，而不是只运行两个时点；记录实际采用的解释。

## 3. 执行与原始记录

1. 用输入包构建图谱，创建包含正向、怀疑、替代、竞争和合规视角的角色。
2. 先跑有界小样检查角色是否能读取候选、生成完整中文/英文文本并执行自主行动；通过后再完成计划轮次。轮次是模拟对话或行动批次，不代表自然月。
3. 结束后从数据库或原始日志直接核验结果，不能只信接口的汇总计数；接口显示 0 但数据库有记录时，保留两者及异常说明。
4. 保存实际轮次、原始行动数、有效自主行动数、被过滤行动数、异常输出、候选相关反向反馈和淘汰理由。

有效自主行动必须是非空、可读、非重复、非种子内容，并且能明确关联某个候选、用户行为、替代选择、竞争响应或政策/合规风险。乱码、截断句、模板回声、重复转述和无关闲聊全部过滤，不得计入有效证据。

## 4. 候选与整次运行的通过标准

候选只有同时满足以下条件，才可进入“优先验证”评估：

- 存在与该候选明确相关的有效自主行动；
- 至少出现一条可分析的质疑、拒绝、替代、失败路径或竞争响应；
- 反向反馈已映射到失效条件或下一验证动作，而非只放在风险附录；
- 没有用角色数、点赞数、行动占比或选择比例冒充市场份额、购买率或人口规模。

候选未达到上述标准时标为“MiroFish 证据不足”，可以继续作为待研究假设，但不得优先开发、预售或生成可售用途素材。

整次运行只有在服务实际完成、标识齐全、原始结果可核验、过滤规则已执行且异常已披露时才算通过。仅启动进程、创建项目、生成图谱或出现若干帖子都不算完成。

## 5. 失败处理

遇到服务不可用、模型/Zep 连接失败、上下文溢出、活动时间解析错误、无有效自主行动、结果无法从数据库或原始日志核验等情况，先进行一次有记录的修复与重跑。仍失败时：

- 将整次技能运行标为“未完成/阻断”；
- 只返回已完成的研究事实、失败位置、异常记录和下一修复动作；
- 不输出候选优先级、开发建议、预售建议或面向销售的产品图；
- 不以人工角色扮演、模型单次问答或“假设已经运行”替代 MiroFish。

## 6. 报告字段

| 字段 | 必填内容 |
|---|---|
| 运行状态 | 通过 / 候选证据不足 / 未完成阻断 |
| 环境 | 日期、MiroFish 版本或提交、模型、上下文配置 |
| 标识 | 项目 ID、图谱 ID、模拟 ID |
| 运行量 | 计划及实际轮次、原始行动数、有效行动数、过滤数 |
| 反向证据 | 按候选列出质疑、替代、失败路径和竞争响应 |
| 异常 | 计数冲突、乱码、截断、重复、解析或服务错误 |
| 决策影响 | 保留、降级、淘汰及其证据链；不得写成购买概率 |
| 下一动作 | 能推翻或解除反证的真实数据、工程或行为测试 |

## 7. 商业边界

正式商业使用前核对 MiroFish、本地/云端模型、Zep 及外部数据源的当前许可和数据条款。许可未核清不影响内部研究记录，但会阻断商业发布与客户交付。

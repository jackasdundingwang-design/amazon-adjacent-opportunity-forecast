# 机会推荐与交付的证据闸门

适用于相邻新品、图案、配色和套装推荐。设计流行、已有供给、内容吸引力、销量增长、市场份额增加是不同命题，分别验证。事实证据可生成假设，不能跨越未验证环节直接变成开发优先级。

## 1. 先找匹配款和反例

在推荐前，按人群、场景、核心配置、人数、材质、图案及配色建立匹配表。主动查找高度匹配的现有款，包含增长、平台、下降的可比样本，不只选成功案例；记录查询范围，未找到不等于不存在。按父体与卖家去重，无法取得足够独立样本时说明。

比较相同完整月、同比同季、最近阶段与上市早期基数；区分季节回升、低基数同比增长、平台波动和持续增长。单月反弹不是加速增长。已存在近似款时，必须说明拟开发款新增了什么可检验的价值，不能把换色或重组现有元素称为新需求。

单款增长乏力可削弱推荐，但不能单独证明某色失败。库存、曝光、价格、促销、上架时间等未核实因素列为未知，不能事后编造“运营不好”维护原推荐。

## 2. 验证数量字段和比较分母

按子ASIN查询不保证得到独立子体销量。检查字段语义、父子关系及同父体兄弟款返回值。多个配色units相同、childUnitSales为空或字段相互冲突时，标“变体销量口径未证实”；不得分摊父销量、把空值当零或用BSR估计替代已验证子体销量。

可尝试当前可用的月度趋势、ASIN销量预估、含变体的商品查询等接口；以响应字段为准，不把某次接口失败推广为所有数据不可得。销量预估必须保留“第三方估算”标签。

份额=目标可比销量/同口径可比集合销量。分母集合、覆盖、父子去重或历史可比性不明时，不声称市场份额增长；可以只报稳定样本集合内的份额，并公开其边界。颜色比较尽量用相同配置、价格及上市阶段，未知曝光/库存混杂须披露。

关键词突增、购买率长段固定或跨接口冲突未解释时，阻断依赖这些字段的增长推断。其他可靠证据仍可独立研究，不机械终止全部任务，也不允许用流行色或播放量补齐数量缺口。

## 3. 增量机制卡（排序前必填）

每条候选填写：

- 新增购买来自谁：原本不买的人、换新/加购者，还是从其他产品转移的购买者？
- 什么可观察变化改变了购买理由？发生时间、适用人群及证据来源是什么？
- 为什么选择该候选而非最接近现有款？预期改善和验证指标是什么？
- 为什么变化可能持续至目标月份？季节、热点衰退或竞争跟进将如何使其失效？
- 增量归属：全品类需求扩大、替代品转移，或本品牌可能抢占份额；后两者不能计为市场净增。
- 支持证据、最强反证、未排除的解释、下一项可以推翻假设的测试。

“好看、适合约会、符合年度色、视频很火”只描述吸引力，不足以回答上述问题。新品无独立历史时，可用可比产品、明确外部变化或行为试验支撑条件假设，但必须说明迁移假设，不能补造预测。

## 4. 决策出口

|证据状态|输出|
|---|---|
|只有设计趋势、供给存在或高播放|待研究候选；不给商业增长优先级|
|机制合理但关键数量/行为证据缺失|待验证假设；先补证据，不推荐直接开发|
|匹配款与反例已核验，数量或行为证据支持具体增量机制，关键口径无未解决冲突|可列优先验证并说明排序理由；仍不等于批准投产或爆品保证|
|关键依据被反证削弱，且没有已证实的新增价值|撤回原排序；当前不建议按该逻辑开发|

研究测试顺序可按信息价值、风险和成本安排，但必须标为“验证顺序”，不能包装成“销量机会排名”。允许最终没有推荐款。推荐用语：“目前未识别到可证实的配色增长机会，暂不建议按换色逻辑开发。”

## 5. 纠错与冻结

用户提供反例时，先核查，再记录原主张、原证据、反证、修订判断和仍未知事项；不以“只是打样建议”回避原排序缺乏证据。预测期未结束不等于已证明长期失败，但提出推荐时的证据不足可以立即认定并纠正。

修订判断另存版本；保留原始预测和原始输入，后续评分不回写。TimesFM只承担数量序列任务；未经数量模型运行的配色判断必须标“定性假设”，不能把失误归咎于模型。

## 6. 反证必须有否决权

痛点存在、问题可解决、解决后有人增购是三个独立命题。差评只支持第一个的线索；不能自动推出后两个。负面校验由代理主动执行，不能等用户提供反例；已检索过但后续未采用的反证属于决策执行失败，不得解释为“数据不够”。

### 必填负面校验卡

在排序、产品方案、出图和预售用途交付前，对拟推进候选检查并保留：

| 字段 | 必须回答 |
|---|---|
| 最接近反例 | 哪个ASIN/产品与目标人群、核心结构、使用场景高度匹配？查了哪些现有款、低星反馈及增长乏力样本？未找到须说明查询边界，不声称没有反例 |
| 失败现象与原因证据 | 用户具体报告什么，来源、时间、变体、样本口径是什么？区分报告的现象、推测机制和已验证根因；低星抽样不推算故障率，弱销量不直接归因于差评 |
| 对应的候选改动 | 哪个改动针对哪个失败机制？若仍沿用同一关键结构，明确继承的风险；换色、软垫、配件增加不能解释未改变的失效问题 |
| 解除反证的证据 | 哪项可核实证据支持改动有效、适用边界是什么？需何种对照、工程审查或实物测试；未实施只写待验证，不将测试计划写成结果 |
| 增量价值与状态 | 为什么会选择它而非现有款，新增购买还是替换？状态为待研究/待验证/可优先验证/不建议按该逻辑开发；注明被阻断的交付、解除条件 |
| MiroFish 反向证据 | 填写项目/模拟 ID、有效自主行动数、候选相关质疑/替代/失败路径及其决策影响；未完成或无候选相关反向反馈时保持阻断 |

关键项未知时，不得升级为开发或预售建议。已知重大反证仍未排除且没有已证实新增价值时，撤回该方案推荐；不能因此断言整个品类没有机会。

此处“开发建议”指商业立项、开模量产或按可售方案推进，不包括为排除反证而进行的工程审查、验证性样机及内部研究；这些动作应明确标为验证，不算已通过商业立项。

### 状态贯穿后续交付

- 同一候选的阻断状态沿报告→设计→图像→营销文案传递。用户说“继续”“先做漂亮”“明天预售”不会使证据自动升级。改名、换色或增加吸盘数量不构成新候选的风险清零。
- MiroFish 是额外的强制验证门，不替代真实竞品、评论、销量、政策或工程证据。其结果只有在按 `mirofish-run.md` 核验后才参与降级、淘汰或下一测试设计，不能单独解除负面校验卡。
- 出图前先查卡片，不以图像工具替代决策。生成图后检查是否暗示已解决的性能、完整受力路径、适配范围和量产状态；效果图不是工程验证。
- 若用户只要内部构思或研究用图，可提供明确标注的未验证假设图，同时保留阻断原因；不称其为理想已解决方案。若明确用于预售，不将未解除关键反证的方案包装成可售产品素材；可提供问题说明或未兑现承诺的意向研究内容，明确不能代替预售准备。
- 承重、防坠落、耐久等实物性能不能靠在线偏好、短时演示或增加部件证明。必须给出与用途相符的验证证据，不自定未经依据的安全阈值。不得凭空建议另一结构为“安全替代”；替代结构同样需要适配与失效审查。
- “只是概念图”“风险写小字”“两只吸盘比一只安全”“用户催着发布”均不是解除阻断的证据。免责声明披露未知，不消除未知。

示例：匹配款有吸附失效报告；候选增加第二只吸盘和软围靠但没有验证。结论是吸附风险仍待排除、软围靠不解决该风险，而不是更可靠的升级款。即使图更好看，也不能升级为预售推荐。
